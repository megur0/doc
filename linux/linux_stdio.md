## ファイルディスクリプタ
* プログラムがアクセスするファイルや標準入出力などを、OSが識別するために用いる識別子。
* `0` … 標準入力
* `1` … 標準出力
* `2` … 標準エラー出力

## tty
* 標準入出力となっている端末デバイス（制御端末、controlling terminal）。もしくはその名前を表示するコマンドのこと。
* `ps` コマンドで「TTY」となっている列が、各プロセスのttyになる。
```
  PID TTY           TIME CMD
 1468 ttys000    0:00.32 /Applications/Xcode.app/Contents/Developer/usr/bin/xcdevice observe --usb
67494 ttys005    0:00.10 -zsh
 5991 ttys007    0:00.13 /bin/zsh -il
27533 ttys007    0:04.72 docker compose up api
```
* 上の例では、同じ `ttys007` に複数のプロセスがぶら下がっている（あるターミナルのウィンドウから起動したプロセス群）ことが読み取れる。

### 現在のターミナルのttyを確認する
```
$ tty
/dev/ttys005
```
* ターミナルで新しいウィンドウを開くごとに違う番号が割り当てられる。
* `w` コマンドで、ログインしているユーザーと実行中のプロセス、および各ttyを確認できる。
* ttyに対して直接echoすることもできる（そのttyの画面に表示される）。
```
echo "aaa" > /dev/ttys005
```

### /proc/[プロセスID]/fd/ で向き先を確認する
* `/proc/[プロセスID]/fd/` 配下を見ることで、プロセスごとのファイルディスクリプタの向き先が分かる。
* 下の例（SSHでアクセスした際の表示）では、標準入力・標準出力・標準エラー出力の全てが `/dev/pts/0` になっている。
```
$ ps
  PID TTY          TIME CMD
 7270 pts/0    00:00:00 bash
 7322 pts/0    00:00:00 vim
 7330 pts/0    00:00:00 ps
$ ls -l /proc/7322/fd
lrwx------ 1 ec2-user ec2-user 64  4月 28 09:14 0 -> /dev/pts/0
lrwx------ 1 ec2-user ec2-user 64  4月 28 09:14 1 -> /dev/pts/0
lrwx------ 1 ec2-user ec2-user 64  4月 28 09:14 2 -> /dev/pts/0
lrwx------ 1 ec2-user ec2-user 64  4月 28 09:14 4 -> /home/ec2-user/.test.txt.swp
```
* 「pts」はSSHやtelnetで接続している仮想端末（pseudo terminal slave）を示す。`/dev/pts/0` は接続しているターミナルの画面にあたる。
* つまり、SSHで接続しているターミナルを標準入力元・標準出力先デバイスとすることで、ターミナル上に文字を表示したり、ターミナルでタイプした入力を受け取ったりできるようになっている。
* 他にも、httpdなどを見ると `2 -> /var/log/httpd/error_log` となっていて、エラーログがファイルに書き出されていることが分かる。

### psでTTYが「?」となっているプロセス
* これはデーモンプロセス。ユーザーが端末から制御するものではなくバックグラウンドで動作するため、ttyが割り当たっていない。
* これらは標準入力・標準出力・標準エラー出力が `/dev/null` になっていることが多い。

## 出力をファイルへリダイレクトする
* 標準出力
    * `コマンド > ファイル名`（追記は `>>`）
* 標準エラー出力
    * `コマンド 2> ファイル名`（追記は `2>>`）
* 標準出力とエラー出力の両方
    * `コマンド > ファイル名 2>&1`
* `2>&1` は、標準エラー出力（ハンドル数値2）を標準出力（ハンドル数値1）へリダイレクトすることを表す。
* ファイルではなく既存のハンドルへリダイレクトする場合は、`&` の後にハンドルの数値を指定する。
* 結果としてこの書式は、標準エラー出力を標準出力へ出力し、さらにコマンドの標準出力をファイルへ出力するため、標準出力も標準エラー出力もファイルへ出力されることになる。
* 順序が重要な点に注意。`コマンド 2>&1 > ファイル名` と書くと、`2>&1` の時点ではまだ標準出力が端末を指しているため、標準エラー出力は端末に出たままになる。
* bash 4以降では `コマンド &> ファイル名` という省略記法も使える。

## sudoしながらリダイレクトしたい場合
* `sudo コマンド > ファイル` と書くと、リダイレクト自体は元のシェル（sudoされていない権限）が行うため、書き込み権限がないファイルにはリダイレクトできない。
* シェルごとsudoで動かす。
```
sudo sh -c "echo 'aaa' >> test.txt"
```

## tee
* 標準出力にも出しつつ、ファイルにも書き出したい場合に使う。
* `-a` で追記。
* (参考) https://qiita.com/laikuaut/items/e1cc312ffc7ec2c872fc

## script
* `script [オプション] ファイル名` で、以降のコマンドと標準出力を記録する。
* Amazon Linuxにも標準で入っている。
* `-a` で追記。
* `exit` もしくは `Ctrl-D` で記録を終了する。
```
sudo script -a /var/log/log_`date "+%Y%m%d_%H%M%S"`
```

## psacct
* プロセスアカウンティング。どのユーザーがどのコマンドを実行したかを記録する。
