## デーモンとプロセスの種類
* デーモンとは
    * メモリ上に常駐しているプログラムの、UNIX系OSにおける呼び名。バックグラウンドプロセスとして動作し続けるプログラムを指す。
    * 名前の最後に「d」を付けるのが慣例になっている。httpd、ftpd、syslogd など、末尾に「d」が付いていればデーモンだと判断してよい。
* フォアグラウンドプロセス（ジョブ）
    * 端末に紐づき、実行中は端末を占有する通常のプロセス。
* バックグラウンドプロセス（ジョブ）
    * 端末を占有せずに動作するプロセス。

## ジョブの操作
* `Ctrl-z` … ジョブを一時停止
* `fg` … 直近のジョブをフォアグラウンドに復帰
* `bg` … バックグラウンドで再開させる
* `jobs` … 実行中のジョブを表示
* `disown` … ログアウトしてもジョブが終了しないようにする
* `&` を末尾に付けるとバックグラウンドで実行する
    ```
    sort address > result &
    ```
    * `jobs` でバックグラウンドで実行されていることを確認できる。
* 複数のコマンドを `&` でつなぐと、それぞれがバックグラウンドで並行して実行される。
    ```
    command1 & command2 & command3 &
    ```
* `nohup` を先頭に付けると、ログアウト後もコマンドを実行し続けられる。
    ```
    nohup updatedb &
    ```
* (参考) https://tech.nikkeibp.co.jp/it/article/COLUMN/20060224/230589/

## シグナル
* `kill -l` で種類や番号を確認できる。
* `kill -s 9 <PID>`、`kill -KILL <PID>`、`kill -9 <PID>` はいずれも同じ。
* 代表的なもの（番号はLinuxのx86/ARMの場合。アーキテクチャによって異なることがあるため、番号ではなく名前で指定する方が安全）
    * SIGHUP（=1, hangup） … ターミナル終了時にログインシェルによって送信される
    * SIGINT（=2, interrupt） … `Ctrl-C` で送信される
    * SIGKILL（=9） … 強制終了。プロセス側で捕捉・無視できない
    * SIGTERM（=15, termination） … `kill` コマンドで `-s` オプションを指定しなかった場合に送信される。プロセス側で終了処理を行える
    * SIGCONT（=18） … 再開
    * SIGSTOP（=19） … 停止。SIGKILLと同様に捕捉・無視できない
    * SIGTSTP（=20） … `Ctrl-z` で送信される停止シグナル。こちらは捕捉できる
* プロセスによってはSIGHUPを無視して処理を継続する。
* 特に一部のデーモンプロセスは、SIGHUPを終了ではなく設定の再読み込み・再起動のために利用する。

## ps
* `ps aux`
    * 端末操作のもの（a）、端末操作以外のもの（x）を含めて表示し、CPUやメモリの使用率等も表示する（u）。
    * 定期的にプロセスの状態は確認しておいた方がよい。意図しないプロセスが動いていないか、メモリ使用率がどの程度か。
* 並べ替え
    * `ps aux --sort -%cpu` … CPU使用率の降順
    * `ps aux --sort -rss` … メモリ使用量の降順
* 主な表示項目
    * `%CPU`、`%MEM` … CPU、メモリの占有率
    * `RSS`（Resident Set Size） … プロセスが実際に物理メモリ上に確保しているサイズ（KB）
    * `VSZ`（Virtual Set Size） … プロセスが確保している仮想メモリのサイズ（KB）。実際に物理メモリを使っているとは限らない
    * `STAT` … プロセスの状態
        * `R` 実行中または実行可能
        * `S` 割り込み可能な待ち状態（スリープ）
        * `D` 割り込み不可能な待ち状態（多くはI/O待ち）
        * `T` 停止中（`Ctrl-z` などによるサスペンド）
        * `Z` ゾンビプロセス（すでに終了しているが親プロセスが終了ステータスを回収していない）
    * `TIME` … プロセスの総CPU実行時間
* 参考）mallocやfreeでのVSZ・RSSの挙動
    * (参考) https://nopipi.hatenablog.com/entry/2017/11/11/213214

## pstree
* 現在動作しているプロセスをツリー形式で表示するコマンド。
* 「どのプロセスからどのプロセスが起動しているのか」という親子関係が分かりやすく表示されるので、システムの仕組みを学習するのにも役立つ。
* 単独で実行すると全てのプロセスがツリー形式で表示される。量が多いので `more` などと組み合わせるとよい。
* 罫線が自動で `-` や `+` などの記号になるが、罫線文字を使いたい場合は `-U` を付ける。
```
pstree -U | more
```
```
pstree <ユーザー名>   # 指定したユーザーのプロセスのみ表示
```

## screen
* 長時間かかる作業を行う際に使うターミナルマルチプレクサ。SSHが切断されてもセッションが維持される。
* nohupより自由度が高く、後からセッションに再接続して経過を確認できる。
* (IMO) 現在は同種のツールとしてtmuxの方がよく使われる。新しく覚えるならtmuxでよい。
* 使い方の例
    1. sshでログインする
    2. `screen` でセッションを開始する
    3. コマンドを実行する
    4. `Ctrl-a` の後に `Ctrl-d` でデタッチ（セッションから抜ける。処理は継続する）
    5. `screen -ls` でセッションの一覧を確認する
    6. `screen -r <セッションID>` でアタッチ（再接続）する
    * `Ctrl-a` の後に `k` で現在のセッションを削除する。
* (参考) https://qiita.com/ryounagaoka/items/8203e9c149b542986c92

## nohup
* ログアウトしてもハングアップされずに、コマンドの実行を継続する。SSHを切断してもコマンドが動き続ける。
* 通常はプロセスを起動した親プロセス（ログインシェル）がプロセスを監視しており、親プロセスが終了するとSIGHUPによって子プロセスも終了させられる。nohupはこのSIGHUPを無視するようにプログラムを実行する。
* 結果はデフォルトでは `$HOME/nohup.out` に追記される。追記されていくため、出力先を明示的に指定した方が分かりやすい。
    ```
    nohup ./batch.sh > out.log 2>&1 &
    ```
* SSH経由で使う場合は、標準入力も `/dev/null` に向けて閉じておく。標準入力が端末に繋がったままだと、SSHセッションの終了処理がその入力を待ってしまい、ログアウトがハングすることがある。
    ```
    nohup ./batch.sh < /dev/null > out.log 2>&1 &
    ```
    * (参考) https://www.qoosky.io/techs/9dd96483ab
* nohupで実行中のプログラムを終了させるには、プロセスIDを調べて `kill` する。
* 複数のコマンドをまとめて実行したい場合は、シェルを一枚かませる。
    ```
    nohup sh -c 'sleep 5; echo done' &
    ```
* (参考) https://www.codereading.com/nb/ignore-the-hangup-signal.html
