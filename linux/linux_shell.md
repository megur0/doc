## 基本的なコマンド
* `man <コマンド>` … マニュアルを表示
    * 例）`man arch`
* `history` … コマンド履歴
* `alias` … 設定されているエイリアスを確認
* `which <コマンド>` … コマンドの実体のパスを確認
* `echo`
    * `-e` エスケープシーケンスを解釈する
    * `-E` エスケープシーケンスを解釈しない
    * どちらがデフォルトかはシェル・環境によって異なる(?)。bashのビルトインでは `-E`（解釈しない）がデフォルトだが、zshのビルトインは解釈する側がデフォルトになっている。
        * `echo -e "あ\nい\nう"`
* コマンドの結果を別のコマンドの中で使う（コマンド置換）
    * `$(コマンド)` もしくは `` `コマンド` ``
    * 入れ子にできる・エスケープが素直という理由から `$( )` の方が推奨される。
* `sort`
    * `-n` 文字列を数値と見なして並べ替える / `-r` 逆順で並べ替える
    * 例）`du -sh ./* | sort -nr`

## 環境変数
* 環境変数の確認
    * `env`
* 環境変数を.envファイルから読み込む
    ```
    set -a; source .env; set +a;
    ```
    * `set -a` で、以降の変数定義を `export` 扱い（環境変数として定義）にできる。
    * (参考) https://qiita.com/YumaInaura/items/50b744d79fb61afb447b
    * (IME) このコマンドを実行しても `env` で表示すると想定どおり上書きされていないことがあった。シェルの起動プロセスが分かれている場合（Dockerのentrypoint経由など）、`set -a` を実行したシェルとは別のプロセスでコマンドが動いていることが原因になりやすい。
* 一時的に環境変数を設定した状態でコマンドを実行する
    * `env LANG=C date`
    * `env` は省略できる
        * `LANG=C date`
    * あくまでそのコマンドの実行中だけ変わっている点に注意。
* `$$` … 自分自身のPID
    * `echo $$`

## シェルの種類
* 現在使っているシェルの確認
    * `echo $SHELL`
* 主な種類
    * sh（Bourne Shell）
    * bash（Bourne Again Shell）… shを大幅に強化したもの
    * ksh
    * csh
    * tcsh
    * zsh … macOSでは現在これがデフォルトのログインシェル
* シェルスクリプト側から明示的に環境設定を読み込ませたい場合、`#!/bin/bash -login` のように書くことで、ログインシェルとしての初期化（`~/.bash_profile` の読み込み）を意図的に行わせることができる。

## ログインシェル・インタラクティブシェル・非インタラクティブシェル
* (参考) https://qiita.com/incep/items/7e5760de0c2c748296aa
* ログインシェル
    * bashをプログラムとして起動するとき、オプション `-` または `--login` が付加された際に起動するシェル。
    * `ssh user@host`、`su - [user]`、`bash --login`、macOS Terminal.appの新規ウィンドウ／タブ、tmuxの新規ウィンドウなどで起動する。
    * 起動時に `~/.bash_profile` を実行する。
        * ほとんどの場合 `~/.bash_profile` の中に `~/.bashrc` を実行する記述がある。ログインシェルでは `.bashrc` が自動実行されるわけではないため。
* インタラクティブシェル
    * オプション `-c` を付加されずに起動され、標準入出力が（仮想）端末に接続されているシェル。インタラクティブシェルの全てがログインシェルであるとは限らない。
    * 次のようなコマンドではログインシェルではなく、純粋なインタラクティブシェルが起動される。
        * `su [user]`
        * `bash`
    * 起動時に `~/.bashrc` を実行する。
        * 多くの場合、`~/.bashrc` の中からシステム標準のbashrc（例: `/etc/bashrc`。ディストリビューションにより異なる）も実行するよう記述されている。
* 非インタラクティブシェル
    * `su user -c /path/to/command`、`bash -c /path/to/command` などで起動するシェル。

## コマンドの連携
* `コマンド1 ; コマンド2`
    * コマンド1が終了したらコマンド2を実行する（実行結果に関わらず）。
* `コマンド1 | コマンド2`
    * パイプ。コマンド1の標準出力をコマンド2の標準入力に渡す。
* `コマンド1 || コマンド2`
    * コマンド1が異常終了したらコマンド2を実行する。
* `コマンド1 && コマンド2`
    * コマンド1が正常終了したらコマンド2を実行する。
* `コマンド1 & コマンド2`
    * コマンド1をバックグラウンドで実行しつつコマンド2を実行する。
    ```
    sh /home/user/batch.sh >> /var/log/batch.log & vi /home/user/memo.txt
    ```
* `コマンドA | xargs コマンドB`
    * コマンドAの実行結果を引数にしてコマンドBを実行する。
    * (参考) https://qiita.com/egawa_kun/items/714394609eef6be8e0bf

## `--` の意味
* Double Dash（ダブル・ダッシュ）と呼ばれ、UNIXにおけるコマンドフラグの終わりを示す記号。
* これ以降の引数は、スキャンのモードによらずオプションとして解釈されなくなる。
* 例）`npm run dev -- --watch`
    * `npm run` コマンド自身へのオプション指定なのか、`npm run` 以降に指定したnpm-scriptsへのオプション指定なのか区別が付かないため、ダブル・ダッシュで境界を明示する。
* 例）`rm -- -some.txt`
    * ハイフンから始まるファイル名を指定したい場合。

## カーソル移動・行編集（Emacsキーバインド）
* `Ctrl-A` 行頭へ
* `Ctrl-E` 行末へ
* `Ctrl-U` カーソル位置から行頭まで削除
* `Ctrl-K` カーソル位置から行末まで削除
* `Ctrl-W` カーソル位置の直前の単語を削除
    * `mv` コマンドで引数の順序を間違えたときなど、単語単位で消せると速い。
* `Ctrl-H` カーソルの左の1文字を削除
* `Ctrl-Y` 直前に削除した文字列を貼り付け
* `Ctrl-R` コマンド履歴の検索
* `Ctrl-D` 入力途中に押すとカーソル位置の文字を削除。何も入力していない状態で押すと入力の終了（EOF）
* `Ctrl-C` 実行中のコマンドを中断
* macOSのターミナルでは、Optionキー＋カーソルで単語単位の移動、Commandキー＋カーソルで行頭・行末への移動ができる（ターミナルアプリの設定による(?)）。

## 矢印キーが使えない場合
* ヒストリー機能を持たないシェル（`sh` など）では、矢印キーがそのままコントロールコードとして表示されてしまう。
* `/bin/bash` や `/bin/zsh` など、行編集機能（readline等）を持つシェルを使えば解決する。
* (参考) https://teratail.com/questions/23286

## 長いコマンドの改行
* 行末にバックスラッシュを置くと継続行になる。
```
somecommand --optionA=xxxx \
      --optionB=yyyy \
      --optionC=zzzz \
      --optionD=wwww
```
