## グループ
* グループには2種類ある。
    * プライマリグループ（メイングループ）
        * 一人のユーザーがメインで所属するグループ。一般的にはユーザー名と同じグループ名で登録されていることが多い。
        * ユーザーは必ずどこかのプライマリグループに属する。
    * サブグループ（補助グループ）
        * プライマリ以外で所属しているグループ。複数登録できる。
* 一覧
    * `groups` … 自分が所属するグループ
        * 出力例: `ec2-user adm wheel systemd-journal docker`
    * `getent group` … グループ一覧を表示（`cut -d: -f1 /etc/group` でも同様）
* 所属の確認
    * `getent group wheel` … wheelグループに所属するユーザーを確認
    * `groups <ユーザー名>` … 指定したユーザーが所属するグループを確認
* 追加
    * `sudo groupadd <グループ名>`
    * `less /etc/group` で確認できる。
* グループ名やGIDの変更には `groupmod` を使う。グループパスワードの設定は `gpasswd` で行う（グループパスワード自体は現在ほとんど使われない）。

## ユーザー
* ユーザーのホームディレクトリ
    * 一般ユーザーのホームは `/home/<ユーザー名>` に置かれる。各ユーザーのホームディレクトリのパスは `/etc/passwd` に記載されている。
* ユーザー一覧
    * `cut -d: -f1 /etc/passwd`
* `whoami` … 現在のユーザー名
* ID確認
    * `id` … 現在のユーザーのID情報
    * `id <ユーザー名>` … 指定したユーザーのID情報
    * 出力例
        ```
        uid=1000(ec2-user) gid=1000(ec2-user) groups=1000(ec2-user),4(adm),10(wheel),190(systemd-journal),992(docker)
        ```
        * uid（user id） … ユーザーの登録番号とユーザー名
        * gid（group id） … プライマリグループの番号とグループ名
        * groups … 所属するグループの番号と名前の一覧
* ログイン中のユーザー
    * `users`（もしくは `who`）
    * ユーザーを強制ログアウトさせる
        * `w` でログイン情報を確認
        * `ps ax | grep sshd` で該当のセッションのプロセスIDを特定
        * `kill -9 <プロセスID>`（もしくは `kill -KILL <プロセスID>`）
* ユーザーの変更
    * サブグループの変更
        * `usermod -aG <グループ> <ユーザー>`
        * `-aG` はサブグループへの追加。`-G` だけだと現在のサブグループがまるごと置き換わってしまう点に注意。
* ユーザー追加
    * `useradd -g users -s $(which bash) -m app`
        * プライマリグループを `users` に指定し、ログインシェルを指定して `app` ユーザーを作成する。ログインシェルを指定しなかった場合はデフォルト設定が使われる。`-m` はホームディレクトリが存在しない場合に作成するオプション。
* パスワード設定
    * `passwd <ユーザー名>`

## スーパーユーザーへの切り替え
* `su [オプション] [ユーザー名]`
    * `-` … 環境変数を引き継がず、ログインシェルとして起動する
    * `-m` … 環境変数 `USER` と `LOGNAME` を切り替え後のユーザーに引き継ぐ
    * `-c` … ユーザーを切り替えた後で、`-c` の後に記述されたコマンドを実行する
* `sudo su -` でスーパーユーザーに切り替える。
* ハイフンの意味について
    * 「カレントディレクトリを切り替え先ユーザーのホームディレクトリに移動するだけのオプション」と説明されていることがあるが、これは正確ではない。
    * 正確には「現在のシェルの環境変数をすべて解除し、その上で指定したユーザーとしてログインシェルを起動し、カレントディレクトリをそのユーザーのホームディレクトリとする」という意味になる。
    * したがってハイフンを付けないと、切り替え後のユーザーで本来使えるはずのコマンドが `PATH` に載らず、実行できないことがある。
    * (IME) `sudo su root` でrootになったところ、そのユーザーで通常使えるはずのコマンドが見つからず原因の切り分けに時間を取られたことがある。原因は環境変数（特に `PATH`）が切り替え前のまま引き継がれていたことだった。ハイフンを付ければ解決する。
* `sudo -u app /bin/bash --login`
    * appユーザーとしてログインシェルを起動する。

## 権限
* 基本
    * 読み（R）: 4 / 書き（W）: 2 / 実行（X）: 1 / なし: 0
    * これらを足した数値で表現する（例: 読み書き実行 = 7、読み実行 = 5）。
* ファイルの権限一覧
    * `ls -la`
        * `drwxrwxrwx` の形式で表示される。先頭の `d` はディレクトリを表し、以降は所有者・所有グループ・その他の順に権限が並ぶ。その後にリンク数、所有者、グループと続く。
    * `ls -F <パス> | grep /` … ディレクトリのみ表示
    * `ls -F <パス> | grep -v /` … ファイルのみ表示
    * `ls -lSr` … サイズ昇順（`r` はリバース）
* 変更
    * `chmod`
        * `-R` で再帰的に適用する。
        * シェルスクリプトに実行権限を付ける
            * `chmod +x docker-entrypoint.sh`
    * `chown [オプション] ユーザー[:グループ] ファイル`
        * 指定したファイルやディレクトリのユーザー所有権（所有者）やグループ所有権（グループ）を変更する。
        * `-R` で配下も含めて変更する。
        ```
        chown ec2-user:ec2-user /home/ec2-user/.ssh/id_rsa
        ```

## wheelグループについて
* rootになれる条件が「rootのパスワードを知っている」だけだとセキュリティ上不十分なので、加えて「特定のグループに所属している」という条件を課す仕組みがある。
* 慣習的にそのグループが「wheel」と呼ばれている。
