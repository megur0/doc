## 基本
* `cat <ファイル>` … ファイルの内容を表示
* `touch <ファイル>` … 空ファイルを作成（既存ファイルの場合はタイムスタンプを更新）
* `mkdir`
    * `-p` 親ディレクトリも必要に応じて作成する
* `wc -l <ファイル>` … 行数を数える
* `locate <ファイル名>` … ファイルの場所を検索（あらかじめ作成されたデータベースを参照するため高速。`updatedb` で更新される）
* `: > <ファイル名>` … ファイルの中身を空にする

## cp
* `cp <コピー元> <コピー先>`
* `-R`、`-r`（`--recursive`） … コピー元にディレクトリを指定した場合、再帰的に（サブディレクトリも含めて）コピーする
* `-a` … サブディレクトリや属性なども含め、可能な限り全てを保持しながらコピーする（`-dR --preserve=all` と同様）
    * `cp -ap` という書き方をよく見かけるが、`-a` は `-p` の内容を含んでいるため冗長。
* `-p` … パーミッションと所有者とタイムスタンプを保持する（`--preserve=mode,ownership,timestamps` 相当）
* `-f` … 強制的に上書きする
* `-i` … 上書きするかどうか確認する

## mv
* 名前変更
    * `mv <変更前のファイル名> <変更後のファイル名>`
* 移動
    * `mv <ファイル名> <移動先のディレクトリ>/`
* `-i` … 上書きの確認をする（デフォルトでは確認なしに上書きされる）

## rm
* `-f` … 確認なしで削除する
* `-r` … ディレクトリを再帰的に削除する
* ワイルドカードと組み合わせる際は、先に `ls` で同じパターンを実行して対象を確認してから実行する。

## rsync
* `cp` より高機能で、除外指定や差分転送ができる。リモートホストとの同期にも使える。
```
rsync -ahvn --progress <ユーザー名>@<ホスト>:/var/www/html/* /var/www/html/ --max-size=10M
```
* `-a` … なるべくコピー元のファイルと同一条件でコピーする
* `-h` … ファイルサイズの表示を読みやすくする
* `-v` … 詳細を出力する
* `-n`（`--dry-run`） … 実際には転送せず、対象ファイルを確認する
* `--max-size` … 転送対象のファイルサイズの上限を指定する
* `--progress` … 転送状況を表示する
* `--exclude` … 除外するパスを指定する
```
rsync -a /src/ /dest/ --exclude '/tmp/'
```
* コピー元のパスの末尾にスラッシュを付けるかどうかで挙動が変わる（付けると「ディレクトリの中身」、付けないと「ディレクトリそのもの」がコピーされる）点に注意。

## less / more
* `less` は `q` で終了する。`more` もほぼ同じだが、`more` は末尾までいくと終了する。
* 検索は `/` で前方、`n` で次の候補、`N` で前の候補。
* `SPACE` で1画面進む、`b` で1画面戻る。
* (参考) https://qiita.com/inokou/items/a73bac8c7e03951d07be

## head / tail
* `tail -n 10 <ファイル>` … 末尾10行を表示（`-n 10` は省略してもデフォルトで10行）
* `head` は先頭から表示する。
* `tail -f <ファイル>` … 追記を監視し続ける（ログの確認に使う）

## grep / egrep
* `-v` … マッチしない行を表示する
* `-i` … 大文字小文字を区別しない
* `-r` … サブディレクトリを再帰的に検索する
* `-n` … 行番号を表示する
* `egrep` は拡張正規表現が使える grep の別名。現在は `grep -E` の使用が推奨されている（`egrep` は非推奨扱い）。

## find
* まとめて権限を変更する
```
find ./ -type f -exec sudo chmod 644 {} \;
```
* `-type f` はファイル、`-type d` はディレクトリを対象にする。
* `-exec` の終端は `;` だが、シェルが解釈してしまうためバックスラッシュでエスケープする。
* 検索と組み合わせる
    ```
    find config/ -type f | xargs grep storage_path | grep framework
    ```
    * configフォルダ以下のファイルから `storage_path` を含むものを検索し、さらにそこから `framework` を含む行のみ表示する。
* 変更があったファイルを表示する
    ```
    find ./ -mmin -120
    ```
    * 120分以内に変更があったファイルを検索する。
    * (参考) https://qiita.com/narumi_/items/9ea27362a1eb502e2dbc
* まとめてリネームする
    ```
    brew install rename
    find ./ -type f -name "*.txt" | xargs rename 's/\.txt$/.md/'
    ```
    * (参考) https://qiita.com/shuhei/items/cf1ddf373d1f83d5d667

## リンク
* ハードリンク
    * ファイルの実体を直接指すリンク。Linuxではファイルの実体が一つでも、その実体を参照するファイル名を複数作ることができる。
    * `ln fileA fileB`
    * コピーに近く見えるが実体は同一なので、`fileA` の中身を変更すると `fileB` にも反映される。
    * ファイルシステムをまたぐことはできず、ディレクトリに対しては通常作成できない。
* シンボリックリンク
    * ファイルやディレクトリの場所（パス）だけを持っているファイル。
    * `ln -s fileA fileB`
    * ファイルシステムをまたげるが、リンク先が削除されるとリンク切れになる。

## tree
* ディレクトリ構造をツリー形式で表示する。
* インストール: `brew install tree`（macOS）
```
tree .              # カレントディレクトリ配下のツリーを出力
tree ./some-dir/    # ディレクトリを指定
tree -d .           # ディレクトリのみ出力
tree -L 2 .         # 2階層まで表示
tree -h .           # ファイルサイズも出力
```

## 圧縮・アーカイブ
* 用語の整理
    * gz（GNU zip） … ファイルを圧縮するためのアルゴリズム・形式。単一ファイルの圧縮のみを行う。
    * tar（tape archive） … ディレクトリや複数ファイルを一つにまとめるアーカイブ機能。圧縮機能は持っていない。
    * zip … アーカイブ機能と圧縮機能を併せ持つフォーマット。Windowsで主流。
* Linuxでは、tarでアーカイブしてからgzで圧縮するのが一般的。
    * 圧縮: `tar -zcvf archive.tar.gz <ディレクトリ>`
    * 解凍: `tar -zxvf archive.tar.gz`
    * オプションの意味: `c` は create、`x` は展開、`v` は実行状況を表示、`f` は対象ファイル名の指定、`z` はgzipによる圧縮。
    * (参考) https://qiita.com/supersaiakujin/items/c6b54e9add21d375161f
* gzファイル単体の解凍: `gzip -d file.gz`

## リモートで圧縮してローカルにダウンロードする
* 方法1: リモート側で圧縮した結果を標準出力に流し、ローカル側でファイルに書き出す
    ```
    ssh <ユーザー名>@<ホスト> "tar -zcf - /path/to/dir" > ./archive.tar.gz
    ```
    * `-f -` によって、アーカイブをファイルではなく標準出力に書き出している。それをSSH経由でローカルのファイルにリダイレクトしている。
    * (参考) https://orebibou.com/ja/home/201502/20150205_001/
* 方法2: リモート側で圧縮ファイルを作成しておき、scpで転送する
    * (IME) この方法はリモート側に圧縮ファイル分の空き容量が必要になる。ディスクの残り容量が少ないサーバーでは使えず、方法1に切り替える必要があった。
